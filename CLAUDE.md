# CLAUDE.md

TheAlgorithms/Python is an educational collection of algorithms, one algorithm per
file, grouped by topic. Implementations favor clarity and correctness over raw
performance. There is no application to run; the unit of work is a single file.

## Layout

- ~40 topic directories at the root (`maths/`, `sorts/`, `data_structures/`,
  `graphs/`, `ciphers/`, `machine_learning/`, `dynamic_programming/`, ...). Each file
  is a standalone algorithm with its own doctests.
- `scripts/` holds repo tooling (`build_directory_md.py`, `validate_filenames.py`).
- `docs/` is the Sphinx docs build.
- `DIRECTORY.md` is auto-generated by `scripts/build_directory_md.py` (the
  `directory_writer` workflow). Never hand-edit it.

## Commands

This repo uses `uv` and Python >= 3.15, not pip or poetry.

- Install deps: `uv sync --group=test`
- Run tests: `uv sync --group=test` first, then `uv run pytest`. pytest lives in the
  test group, so without the sync `uv run pytest` can fall back to a system pytest on
  the wrong Python. pytest is configured with `--doctest-modules`, so this runs every
  file's doctests. One file: `uv run pytest maths/fibonacci.py`
- Lint (must pass): `uvx ruff check .` or `uvx ruff check <file>`
- Format: `uvx ruff format <file>`
- Type check (advisory only): `uv run --with ty ty check <file>`
- Run everything CI runs at once: `pre-commit run --all-files`

## Conventions

- Every function has a doctest and type hints on all parameters and the return.
- Return the result. Do not `print()` or `plot()` inside an algorithm.
- Raise an exception on invalid input instead of returning something wrong.
- `snake_case` file and function names (enforced by `scripts/validate_filenames.py`),
  `CamelCase` classes, `UPPERCASE` constants. Expand acronyms:
  `greatest_common_divisor`, not `gcd`.
- One algorithm per pull request. Do not change code and its doctests in the same PR.

## Guardrails

- Do not hand-edit `DIRECTORY.md`; it is generated.
- Do not create new top-level directories; fit the work into an existing one.
- There is no `requirements.txt` and no `setup.py`, so `pip install -r
  requirements.txt` fails. Use `uv sync`.
- The repo pins `target-version = "py315"` for ruff. A stock or older ruff errors
  with `unknown variant 'py315'`. Run ruff through uv (`uvx ruff check`) so it uses
  the pinned version, or `ruff check --isolated <file>` for a quick local read.
- `python -m doctest <file>` prints "Test passed" even when the file has zero
  doctests. A missing doctest still fails review, so check the summary, do not trust
  a bare pass.
- A PR whose template has no checked box is auto-closed by the `algorithms-keeper`
  bot. Tick a box in `.github/pull_request_template.md` before opening one.
